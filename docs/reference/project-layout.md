# Project layout

The repository root holds repository-level files (package manifests, build
files, documentation, CI) and the query assertion tests in `test/`. Each
grammar is its own directory with the same four parts (`grammar.js`, `src/`,
`queries/`, `test/`), and anything two grammars share lives in `common/`.

```
common/
  define-grammar.js     the grammar of both ucode and ucode_markup (edit this)
  scanner.h             the external scanner of both code grammars (edit this)
ucode/                  scripts
  grammar.js            entry point: defineGrammar('ucode')
  src/scanner.c         shim: exports the entry points, includes ../../common/scanner.h
  src/                  otherwise generated
  queries/              queries for ucode, and the source of ucode_markup's (edit these)
  test/corpus/          corpus tests
ucode_markup/           templates
  grammar.js            entry point: defineGrammar('ucode_markup')
  src/scanner.c         shim, as in ucode/
  src/                  otherwise generated
  queries/              generated from ucode/queries/ by scripts/generate-markup-queries.js
  test/corpus/          corpus tests
  test/tag-docs/        doc-attachment fixtures for tags.scm
ucdocs/                 doc comments; a standalone grammar
  grammar.js            (edit this)
  src/scanner.c         hand-written scanner: star runs in prose (edit this)
  src/                  otherwise generated
  queries/              (edit these)
  test/corpus/          corpus tests
test/highlight/         highlight assertion tests (.uc: ucode, .ut: ucode_markup)
test/tags/              tags assertion tests
editors/helix/queries/  generated queries for Helix, one directory per Helix language
bindings/               c, go, node, python, rust, swift
scripts/                generators, test runner, validators, editor checks
docs/                   this site
mkdocs.yml              site configuration
tree-sitter.json        grammar manifest
```

## Generated files

| Path | Generated by |
| --- | --- |
| `ucode/src/` (except `scanner.c`) | `tree-sitter generate ucode/grammar.js --output ucode/src` |
| `ucode_markup/src/` (except `scanner.c`) | `tree-sitter generate ucode_markup/grammar.js --output ucode_markup/src` |
| `ucdocs/src/` (except `scanner.c`) | `tree-sitter generate ucdocs/grammar.js --output ucdocs/src` |
| `ucode_markup/queries/` | `node scripts/generate-markup-queries.js` |
| `editors/helix/queries/` | `node scripts/generate-helix-queries.js` |

All are committed; CI regenerates them and fails on any difference, including
new untracked files.

## Build files

The bindings' build files sit at the root:

| File | Builds |
| --- | --- |
| `binding.gyp` | the Node.js binding |
| `Makefile` | the C libraries (one per grammar) |
| `CMakeLists.txt` | the C libraries, with CMake |
| `Cargo.toml`, `bindings/rust/build.rs` | the Rust crate |
| `go.mod` | the Go module |
| `pyproject.toml`, `setup.py` | the Python package |
| `Package.swift` | the Swift package |

## Build output

| Path | Content | Ignored by git |
| --- | --- | --- |
| `.build/parsers/` | parsers built by `scripts/run-tests.js` (`<grammar>.so`, `.dll` on Windows) | yes |
| `.build/c-test/` | the install prefix of `make test-c` | yes |
| `build/` | the Node.js binding (node-gyp) | yes |
| `lib*.a`, `lib*.so`, `*.pc` | `make` output | yes |
| `site/` | `mkdocs build` output | yes |
