# How to change a query

## Edit the source, then regenerate

| Query files | Status | Edit |
| --- | --- | --- |
| `ucode/queries/*.scm` | source; also the source of the `ucode_markup` copies | yes |
| `ucdocs/queries/*.scm` | source | yes |
| `ucode_markup/queries/*.scm` | generated by `scripts/generate-markup-queries.js` | no |
| `editors/helix/queries/*/*.scm` | generated by `scripts/generate-helix-queries.js` | no |

Every code query applies to both code grammars. Edit the file under
`ucode/queries/`, then regenerate the template copy and the Helix copies:

```sh
node scripts/generate-markup-queries.js
node scripts/generate-helix-queries.js
```

`npm run build` runs both, in that order. Commit the regenerated files with
your change.

## Template-only patterns

The few patterns that apply only to templates are not in any `.scm` file:

- the tag-delimiter highlights and the `{# #}` comment highlight, and the
  `tags.scm` patterns for a doc comment in its own tag, live in
  `scripts/generate-markup-queries.js`;
- the Helix highlights for the same nodes live in
  `scripts/generate-helix-queries.js`.

## A new highlight capture

`scripts/generate-helix-queries.js` renames each Neovim capture to its Helix
scope through a mapping table, and fails if a capture has no Helix equivalent.
Add the new name to that table (`HIGHLIGHT_NAMES`, or `HELIX_SCOPES` if Helix
uses the same name).

## Helix indents and text objects

These are not derived from the Neovim files. They are written for Helix inside
`scripts/generate-helix-queries.js`. Edit them there and regenerate.

## Check the result

1. `npm test` compiles every query file against its grammar, checks that every
   token of every corpus input is highlighted (by both the Neovim and the Helix
   highlights), and runs the highlight and tags assertion tests. See
   [Test suites](../reference/test-suites.md).
2. If you changed indents, folds or text objects, run the editor checks: see
   [Check the editor queries](check-editor-queries.md). Helix silently ignores
   an `indents.scm` it cannot compile, so no CLI check catches that.
3. To pin the behavior, add an assertion to `test/highlight/` or `test/tags/`.
